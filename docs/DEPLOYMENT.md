# Deploying to Render (GitHub → Render)

This app deploys as **one Render Web Service** (Node: Express API + the built React site) and **one Render PostgreSQL database**. Everything is described in [`render.yaml`](../render.yaml).

## 1. Push the code to GitHub

From the project folder:

```bash
git init
git add .
git commit -m "Keyboard Ball Challenge"
git branch -M main
git remote add origin https://github.com/<your-account>/keyboard-ball-challenge.git
git push -u origin main
```

`.env` is in `.gitignore`, so your local secrets are not pushed. Create the empty repository on GitHub first (no README), then run the commands above.

## 2. Create the Blueprint on Render

1. Sign in at <https://dashboard.render.com> and connect your GitHub account.
2. Click **New → Blueprint** and choose the repository.
3. Render reads `render.yaml` and proposes:
   - `kbc-db`: PostgreSQL 16 database
   - `keyboard-ball-challenge`: Node web service
4. Render asks for the values marked `sync: false`. Fill in **one** way to create the first organizer:
   - **Option A (recommended):** `ADMIN_USERNAME` and `ADMIN_PASSWORD` (min 8 characters). The account is created on first start if none exists. After you have logged in and changed the password, you can delete these two variables.
   - **Option B:** `SETUP_TOKEN`, a long random string. Then open `https://<your-app>.onrender.com/setup` and enter it with the username and password you want.
   - Leave the others empty.
5. Click **Apply**. The first deploy takes a few minutes.

What happens on each deploy:

| Step | Command |
|---|---|
| Build | `npm ci --include=dev && npm run build` (installs, generates the Prisma client, builds the React app and the server bundle) |
| Start | `npm run start:prod` → `prisma migrate deploy` (applies new migrations) then `node dist/server/index.js` |
| Health check | `GET /api/health` returns `200 {"status":"ok","database":"ok"}` when the app and database are up |

`JWT_SECRET` is generated by Render automatically. `DATABASE_URL` is wired to the database automatically.

## 3. Check it works

- Open `https://<your-app>.onrender.com/api/health`. You should see `"status":"ok"`.
- Open `https://<your-app>.onrender.com` and log in.

Later pushes to `main` redeploy automatically (`autoDeploy: true`).

## Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | yes | PostgreSQL connection string (set from the Render database) |
| `JWT_SECRET` | yes | Signs session cookies; at least 32 characters (auto-generated) |
| `NODE_ENV` | yes | `production` on Render (enables secure cookies) |
| `SETUP_TOKEN` | one of these | Enables the `/setup` page for the first organizer |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | one of these | Creates the first organizer at startup |
| `SESSION_HOURS` | no | Login lifetime, default 12 |
| `PORT` | no | Set by Render automatically |

## Recovering or adding an organizer

In the Render dashboard open the web service → **Shell**, then:

```bash
npm run admin:create -- <username> <new-password>
```

This creates the organizer, or resets its password if it exists (logging out its old sessions).

## Notes on Render plans

- **Free web services sleep** after about 15 minutes without traffic, and the first request then takes up to a minute. Open the site a few minutes before the event starts, or use a paid instance for the event day. If the service restarts mid-game, the timer is not lost: its end time is stored in the database and screens reconnect on their own.
- **Free PostgreSQL databases expire** after 30 days. For a longer-lived deployment choose a paid database plan in `render.yaml` (`plan: basic-256mb`, for example).
- The live updates (Server-Sent Events) are kept in the server's memory, so run **one instance** of the web service (the default).

## Running on a laptop without internet

If the venue has no reliable internet, run it locally instead (see the README: *Local setup*), build with `npm run build` and start with `npm start`. Everything, including fonts, is served by the app itself; nothing is loaded from external sites.
